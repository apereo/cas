# JWKS - OpenID Connect Authentication

The JWKS (JSON Web Key Set) endpoint and functionality returns a JWKS containing public keys that enable 
clients to validate a JSON Web Token (JWT) issued by CAS as an OpenID Connect Provider.

{% include_cached casproperties.html properties="cas.authn.oidc.jwks.core" %}

## Key Types

Keys generated by CAS are RSA or elliptic curve keys, along with their size or curve (P-256, P-384 or P-521), which can be
defined using CAS properties. Elliptic curve signing keys are published with the signing algorithm of their curve
(`ES256`, `ES384` or `ES512`), while encryption keys carry no algorithm and clients pick one that discovery advertises.
Keystores generated by earlier versions, where elliptic curve keys could carry an algorithm that does not match their
curve, are corrected as they are loaded, without generating new keys.

## Encrypted Request Objects

Clients may encrypt their request objects to CAS, as described by
[OpenID Connect](https://openid.net/specs/openid-connect-core-1_0.html#EncryptedRequestObject): the request object, usually
signed by the client first, is encrypted to one of the encryption keys that CAS publishes in its JWKS and names it with
`kid`. CAS decrypts it with that key, or tries each of its encryption keys when no `kid` is given, and then verifies
the nested request object with the keys of the client like any signed request object. Every encryption key the JWKS
publishes is accepted, whatever its rotation state, so clients that still hold the key set from before a rotation are
not refused.

Only the key management and content encryption algorithms that discovery advertises are accepted: by default `RSA-OAEP`
and `RSA-OAEP-256` for RSA keys and the `ECDH-ES` family for elliptic curve keys, with the AES-CBC-HMAC and AES-GCM
content encryption algorithms. Symmetric key wrapping with keys derived from client secrets is not supported, and
compressed request objects are refused. The advertised algorithms can be adjusted using CAS properties.
